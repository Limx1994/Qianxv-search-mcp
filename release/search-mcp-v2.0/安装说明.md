# Qianxv-search-mcp v2.0 安装说明

本目录及同名 ZIP 提供 Windows 独立版 `search-mcp.exe`，无需安装 Python。
同一套 `search`、`extract` 工具支持 stdio 和 Streamable HTTP。
公开发行包只包含 exe、本说明和 `config.example.json`，不含私有配置。

## 配置

将本目录整体复制到目标机器。如果尚无 `config.json`，先复制
`config.example.json` 为 `config.json`，然后填写自己的 API Key。
已有 `config.json` 时直接编辑，不要覆盖其中的私有配置。
至少配置一个可用的搜索节点；
如需 `extract`，还须配置可用的抓取节点。配置文件须与 exe 同目录。

```powershell
Copy-Item .\config.example.json .\config.json
```

模板不含密钥。`config.json` 含真实密钥，勿上传或分发。
节点配置与故障转移顺序见项目根目录 README。ZIP 用户需先解压，
并保持上述文件位于同一目录。

## 启动与接入

无参数保持 v1.0 的 stdio 行为，可沿用原 MCP 客户端配置，
仅将 `command` 改为本目录 exe 的绝对路径：

```json
{
  "mcpServers": {
    "Qianxv-search-mcp": {
      "type": "stdio",
      "command": "C:/tools/search-mcp/search-mcp.exe",
      "args": []
    }
  }
}
```

在 PowerShell 中独立启动 HTTP 服务：

```powershell
.\search-mcp.exe --transport streamable-http
.\search-mcp.exe --transport streamable-http --port 9000
```

HTTP 客户端选择 Streamable HTTP，连接
`http://127.0.0.1:8000/mcp`（指定端口时替换 8000）。
服务仅监听 `127.0.0.1`，不会接受其他机器的连接。

同一进程同时启用 stdio 与 HTTP 时，在 stdio 客户端的 `args` 中填入：

```json
["--transport", "both", "--port", "8000"]
```

stdio 连接断开后，进程仍会继续提供 HTTP，直到被停止。
若 stdio 客户端主动终止其子进程，HTTP 会一同停止；
需要独立常驻的 HTTP 服务时使用单独启动命令。
端口被占用会报错并停止启动，可用 `--port` 更换。

运行日志写入 exe 同目录的 `logs/mcp_search.log`。
路径在 JSON 中建议使用正斜杠 `/`，以避免反斜杠转义问题。
