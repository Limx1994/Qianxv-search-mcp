# Qianxv-search-mcp 安装说明（v1.0）

本地搜索 MCP 服务发行版：`search`（多搜索源故障转移联网搜索）+
`extract`（网页标题与 Markdown 正文抓取）两个工具，供大模型
（MCP 客户端）调用。已打包为独立 exe，**无需安装 Python**。

> 版本：v1.0 ｜ 更新日期：2026-09-29
> 节点、开关、端点配置见同目录 `config.json`，修改后重启客户端生效。
> 公开发行包中的 API Key 已清空，使用前请在 `config.json` 中填写自己的密钥。

## 包内容

```
search-mcp.exe   MCP 服务（stdio 传输）
config.json      节点配置（含 API 密钥，请妥善保管，勿外传）
安装说明.md      本文件
```

## 安装步骤

1. 将本目录整体复制到目标机器任意位置（路径不要含全角字符更稳妥），
   例如 `C:\tools\search-mcp\`。
2. 在 MCP 客户端配置中加入以下 `mcpServers` 片段
   （`command` 改为 exe 实际绝对路径，**推荐正斜杠写法**）：

```json
{
  "mcpServers": {
    "Qianxv-search-mcp": {
      "type": "stdio",
      "command": "C:/tools/search-mcp/search-mcp.exe",
      "args": [],
      "description": "本地搜索 MCP 服务：search（多搜索源故障转移联网搜索）+ extract（网页标题与 Markdown 正文抓取）"
    }
  }
}
```

> **重要：强烈推荐正斜杠 `/` 写路径**：JSON 中单反斜杠 `\` 是转义字符，
> 会被解析吞掉导致 `MCP error -32000: Connection closed ... 不是内部
> 或外部命令`；且 **CodeBuddy CN 客户端存在转义 bug**，即使写标准的
> 双反斜杠 `\\` 也会再吞一次反斜杠。正斜杠不受影响（Windows 同样识别）。
> 详细排查步骤见下方 FAQ Q1。

3. 重启 MCP 客户端即可使用 `search` / `extract` 工具。

## 注意事项

- `config.json` 必须与 `search-mcp.exe` 放在同一目录，服务启动时
  从 exe 所在目录加载。
- **启动超时建议设为 15 秒以上**：exe 首次启动需自解压
  （约 1~2 秒），之后会常驻。
- 运行日志写入 exe 同目录的 `logs/mcp_search.log`
  （滚动 2MB×3 份），API Key 在日志中自动脱敏。
- 各搜索源有免费额度（AnySearch 每日 1000 次 / 千帆每日 100 次 /
  火山每月 500 次 / Tavily 每月 1000 次），额度耗尽会自动切换
  下一节点，全部失败才报错。
- 更换或增删搜索源：编辑 `config.json` 的 `nodes` /
  `extract_nodes` 数组（顺序即故障转移顺序），`enabled: false`
  可临时停用某节点，改完重启客户端生效。

## 常见问题（FAQ）

### Q1：报 `MCP error -32000: Connection closed ... 不是内部或外部命令`

报错信息里路径的反斜杠全部丢失（如
`D:搜索MCPreleasesearch-mcp-v1.0search-mcp.exe`），按以下顺序排查：

1. **单反斜杠问题**：JSON 中 `\` 是转义符，`"D:\tools\..."` 会被吞成
   `D:tools...`。改用正斜杠 `"D:/..."` 或双反斜杠 `"D:\\..."`。
2. **CodeBuddy CN 转义 bug（实测踩坑）**：即使写成标准的双反斜杠
   `"D:\\搜索MCP\\..."`，CodeBuddy CN 启动时仍会再吞一次反斜杠，
   照样报错。**解决方案：command 一律用正斜杠**
   （`"D:/搜索MCP/release/search-mcp-v1.0/search-mcp.exe"`），
   Windows 完全识别，实测连接成功。
3. 改完配置后需在 MCP 面板手动点重连，或重启客户端；面板上的旧报错
   可能是缓存状态，删除条目重新添加可强制刷新。

### Q2：如何定位是不是客户端的问题

- 本服务自身日志：exe 同目录 `logs/mcp_search.log`——如果里面
  **没有**任何记录，说明进程根本没启动起来（路径/转义问题在客户端侧）；
  有调用记录则说明连接正常。
- CodeBuddy IDE 日志：
  `%LOCALAPPDATA%\CodeBuddyExtension\Logs\CodeBuddyIDE\<日期>\<项目>.log`，
  搜索 `mcp-connect` 可看到每次连接尝试；报 `Connection closed` +
  路径缺反斜杠，即客户端启动命令拼错。
- 验证 exe 本身是否正常：在有 Python + mcp 库的环境运行
  `python test_release.py <本目录路径>`，8 项全过即服务端无问题。

### Q3：连接成功但首次调用慢

exe 首次启动需自解压（1~2 秒），且各搜索源是真实 HTTP 请求
（Tavily 等 2~6 秒属正常），把客户端 MCP 启动超时设为 15 秒以上。
