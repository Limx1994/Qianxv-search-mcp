# Qianxv-search-mcp v2.1 安装说明

> 历史版本：v2.1 ｜ 发布日期：2026-10-03 ｜ Windows 目录版 ｜ 无需安装 Python
> 新版使用说明见 v2.5 发行包内的安装说明。

提供 `search`（联网搜索）和 `extract`（网页抓取）工具，支持 stdio、
Streamable HTTP 及同进程 `both` 模式。

## 包内容与配置

```text
search-mcp.exe       MCP 服务入口
_internal/          完整运行依赖
config.example.json 无密钥配置模板
安装说明.md         本文件
配置说明.md         节点类型、端点与故障转移配置
LICENSE             项目许可条款原文
```

先解压 ZIP，将整个目录复制到安装位置，例如 `C:\tools\search-mcp\`。
必须保留 exe 与完整 `_internal\`，不可只复制 exe 或混用其他版本依赖。
目录版直接使用固定依赖，不进行单文件包的 `_MEI*` 临时解压。

在安装目录用 PowerShell 创建配置，已有私有配置时不要覆盖：

```powershell
if (-not (Test-Path .\config.json)) {
    Copy-Item .\config.example.json .\config.json
}
```

编辑 `config.json`，填写自己的 API Key 并确认节点端点。模板只预置
Tavily 搜索和 AnySearch 抓取，密钥均为空。实际节点及调用顺序由
`nodes` / `extract_nodes` 数组决定，`enabled: false` 可停用节点。
至少配置一个可用搜索节点；使用 `extract` 时还须配置可用抓取节点。
详细节点类型和配置要求见本目录 [配置说明](配置说明.md)。

配置须与 exe 同目录，修改后重启服务。配置缺失或非法会阻止启动；
全部节点禁用时工具返回所有节点不可用。私有配置及日志不得上传或分发，
供应商权限、额度和计费以其控制台为准。

## 启动与接入

无参数时为 stdio。在客户端使用以下 `mcpServers` 片段，替换实际绝对路径：

```json
{
  "mcpServers": {
    "Qianxv-search-mcp": {
      "type": "stdio",
      "command": "C:/tools/search-mcp/search-mcp.exe",
      "args": []
    }
  }
}
```

JSON 路径建议使用正斜杠 `/`；反斜杠须写成 `\\`。

独立启动 HTTP 服务：

```powershell
.\search-mcp.exe --transport streamable-http
.\search-mcp.exe --transport streamable-http --port 9000
```

客户端选择 Streamable HTTP，连接 `http://127.0.0.1:8000/mcp`；
指定端口时替换 URL 的端口。服务仅监听本机。

同时使用 stdio 与 HTTP 时，客户端 `args` 设置为：

```json
["--transport", "both", "--port", "8000"]
```

`--port` 范围为 1–65535，可用于 HTTP 和 `both`，不能用于纯 stdio。
端口被占用时启动失败。`both` 的 stdio 连接断开后 HTTP 继续运行；
客户端若终止子进程，HTTP 一同停止。需要独立常驻时单独启动 HTTP 服务。

## 工具、日志与排错

- `search(query, max_results=5)`：数量参数须大于等于 1，返回来源节点及
  标题、URL、摘要；供应商可能返回少于请求数量的结果。
- `extract(url)`：返回来源节点、标题、URL 和 Markdown 正文；超过
  8000 字符会截断，不能使用 `offset` 或 `snapshot_id` 续读。网页内容不可信，仅作参考。
- 日志位于安装目录 `logs\mcp_search.log`，单文件上限 2,000,000 字节，
  保留 3 个备份。并发实例应使用不同安装目录，或升级 v2.5。日志属于私有数据。
- 连接失败先检查实际路径、配置、完整依赖目录、stderr 和端口；
  无日志不能单独证明进程未启动，未调用节点也可能没有记录。
- 所有节点不可用时检查节点开关、凭证、端点、额度及熔断记录。

## 升级与本版变更

先停止旧进程，替换 exe 和完整 `_internal\`，保留自己的 `config.json`
和 `logs\`。安装路径变化时更新客户端配置，再重新连接。
旧单文件版遗留的 `_MEI*` 仅可在确认属于本项目且未被占用后清理。

v2.1 包含数量参数校验、Bright Data 共享 HTTP client 与独立会话头修复，
沿用目录打包、三种传输和配置位置。现有 v2.0 产物保留。
分页、按进程独立日志属于 v2.5；本版 exe 保持原有行为。

## 验证

需要 Python 开发环境，在仓库根目录设置 `MCP_TEST_EXE` 为本版 exe：

```powershell
$env:MCP_TEST_EXE = (Resolve-Path .\release\search-mcp-v2.1\search-mcp.exe).Path
python -m pytest tests/ --basetemp=release/_test/v2.1-pytest -q
Remove-Item Env:MCP_TEST_EXE
```

无密钥测试自动创建隔离配置，覆盖握手、工具列表、三种传输、端口冲突、
stdio 断开后 HTTP 存续、重复启动、并发运行及 `_MEI*` 残留检查。
未设置环境变量导致发行版测试跳过时，不能宣称发行版验证通过。

真实 API 验证另需有效私有配置，会请求外部服务并消耗额度。将完整发行目录
复制到项目内独立的 `release\_test\v2.1-api\`，仅在那里放置 `config.json`，运行：

```powershell
python release/test_release.py release/_test/v2.1-api
```

该脚本包含 8 项断言，检查握手、工具列表、真实调用和日志落地。
外部 API 失败须单独报告。勿向公开发行目录加入测试配置或日志。
