## 用户需求

用户已在知乎数据开放平台（https://developer.zhihu.com/profile）申请到全网搜索的 Access Secret（`20aad83c...`，记录于 `说明.txt`），要求将其作为第 6 个搜索源接入现有本地搜索 MCP 服务的故障转移链。

## 产品概述

在现有"AnySearch → 百度千帆 → 火山豆包 → Tavily → Bright Data"五源故障转移搜索链末尾新增"知乎全网搜索"节点。节点失败（超时/HTTP 错误/鉴权失败/配额耗尽/空结果）时自动切换下一节点，全部失败才返回错误，对 MCP 客户端透明。

## 核心功能

- 新增 `zhihu` 类型搜索 provider：调用知乎开放平台 `GET /api/v1/content/global_search`，Bearer 鉴权 + 秒级时间戳头，解析 `Data.Items[]` 为标准 `SearchResult`（标题/URL/摘要）
- 配置注册：`config.json` 新节点、`config_loader.py` 类型白名单、`providers/__init__.py` 注册表
- 单元测试（mock，不发真实请求）与 README 文档同步

## Tech Stack

- 沿用项目现有栈：Python 3.10+ / httpx（async）/ dataclass / pytest / ruff，不引入任何新依赖

## Implementation Approach

完整复用项目既有 provider 模式（参照 `providers/tavily.py` 标准结构）：

1. **`providers/base.py`**：新增 `_get_json(url, params)` 异步辅助方法，镜像 `_post_json` 的错误转换约定（TimeoutException/HTTPError/非 2xx/非法 JSON/非 dict → `ProviderError`），供 GET 类 API 复用（DRY，避免在单个 provider 内私造 HTTP 逻辑）
2. **`providers/zhihu.py`**（新建）：`ZhihuProvider(SearchProvider)`

- 端点：`https://developer.zhihu.com/api/v1/content/global_search`（`options.endpoint` 可覆盖）
- 请求：GET，params `{"Query": query, "Count": min(max(1, max_results), 20)}`（官方上限 20）
- 鉴权：复用 `_auth_headers()`（Bearer）+ 追加 `X-Request-Timestamp: int(time.time())`
- 响应解析：`Code != 0` → `ProviderError("biz error: <Message>")`；`Data.Items[]` 映射为 `SearchResult(title=Title, url=Url, snippet=ContentText去<em>标签截断500, source=name)`，与 tavily 的 snippet 截断策略一致
- 校验：`endpoint`/`api_key` 缺失时抛 `ProviderError`（与 tavily/brightdata 相同的前置检查）

3. **注册链**：`config_loader.py` 的 `SUPPORTED_TYPES` 增加 `"zhihu"`；`providers/__init__.py` 导入并在 `PROVIDER_REGISTRY` 注册
4. **`config.json`**：nodes 末尾追加 zhihu 节点（enabled=true、timeout 15s、api_key 填入真实 key、options.endpoint 为官方端点），顺序即故障转移顺序，置于末尾对现有链路零影响
5. **`tests/test_zhihu.py`**（新建）：参照 `tests/test_brightdata.py` 风格（mock `_get_json`，不发真实请求），覆盖：正常解析多条结果、max_results 截断、Code!=0 抛错、空 Items 返回空、缺 api_key/endpoint 抛错、`<em>` 标签清理
6. **`README.md`**：搜索源列表、配置 type 枚举说明补充 zhihu

## 性能与可靠性

- 单次 GET 请求，无额外开销；超时由节点级 `timeout_seconds` 控制，复用现有熔断机制（失败后 60s 窗口内跳过）
- 日志走现有 `search_router`/`logger.py` 脱敏管道，key 不会泄露到日志
